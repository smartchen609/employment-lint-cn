# 2026-09-09 方向决定

## 背景

round3 §9 的验证以对话形式完成，结论：**原假设不成立**。

程序员当事人做过功课后，问题已经问对（"两份固定期限换了主体，能不能拿 2N"），
要的是专业确认而非纠错；真正困惑在实务分歧点（如被迫解除的紧迫性）；
盲区（年假未休等）靠律师例行询问发现。
"签字前拦截误判"这个位置，在维护人的客户群里基本不存在。

维护人重申初衷：一份让劳动者能自己走完仲裁、少走弯路的**手册**，
七八十分即可，公允到站在公司方也不觉得偏。

## 决定

| 项 | 决定 |
| --- | --- |
| 给谁用 | 当事人 |
| 形态 | **手册是骨架，工具是皮。** 先写手册，工具改为手册入口 |
| 范围（原 §17 禁） | 欠薪、加班费、双倍工资差额、工伤、竞业限制、PIP **全部解禁**，分批写 |
| 文书（原 §17 禁） | 允许**模板 + 用户填事实**。工具不发明事实、不替用户选请求事项 |
| 模型接口（原 §17 禁） | 允许，**但只能引用已核验的手册与规则内容**。放最后，手册先行 |
| 上传/OCR | 维持禁止 |
| 永久禁 | 赔偿计算器、风险评分、胜诉率、N/2N 自动结论 —— 替人下判断 |
| 信任结构 | 后端、账户、埋点、CRM、留存、付费墙、首页咨询入口 —— 维持禁止 |

## 不变的东西

- L1：AI 不得自撰法条、条文编号、生效日期、URL
- L3：`page_opened_and_checked` 只能维护人置 true
- 来源注册表 + 守卫测试 + 显式不确定性 —— **这是手册的地基**，
  覆盖可以七八十分，来源必须一百分
- 公允原则：手册必须公允到维护人代理公司方时也不觉得它偏
